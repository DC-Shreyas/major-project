PROJECT NOTES

About this dataset.

The generated property and deed tables are the canonical inputs for this version of the project.

◈

One source for the current workflow.

The model joins synthetic_property_valuation_data.csv with synthetic_registered_deeds_validation.csv using the shared property ID. The app does not require the original listing file, deed records, or guidance PDFs.

Property rows3,000
Covered SRO areas3
Quarter range2023 Q2 — 2024 Q1

How the estimate works

  1. 1
    Build the additive property signal.

    Spline terms encode area, bedrooms, age, and floor, with property-type and SRO terms in an interpretable hedonic component.

  2. 2
    Share market and time context.

    Multi-head attention links functionally similar synthetic micro-markets; a GRU summarizes prior-quarter asking and declared signals.

  3. 3
    Train, calibrate, and constrain.

    An interval-censored loss uses the two price signals. Flagged generated references supervise price, asking-markup, and under-declaration heads; conformal calibration uses 2023 Q4 anchors.

DATA STATUS

Generated records, clearly labeled.

The files contain synthetic values. Model scores only describe how well the model recovers generated reference prices in the held-out quarter.

They are not sale records, independent valuations, or evidence of real Bengaluru prices.

The CSVs contain no coordinates, RERA records, amenity locations, or dated metro milestones. The graph represents functional market similarity, not geographic adjacency.
